## Publishing failure and recovery

The tag-triggered [Windows workflow](https://github.com/khantroll/ForgeBridge/actions/runs/41687424840)
successfully built the EXEs, verified both PE file/product versions and passed
the extracted-EXE smoke tests. **Its publishing job failed**, rather than
attaching the ZIP: `FileNotFoundError: ... 'windows-release/build-summary.json'`.

The real downloaded artifact (`13255510949`) has these paths:

```text
forgebridge-dist/build-summary.json
forgebridge-dist/ForgeBridge-0.11.0-windows-x64.zip
frozen-smoke/...
```

`upload-artifact` retained the common-root directories because build and smoke
evidence were uploaded together. Publishing incorrectly expected both build
files at the artifact root. This is a packaging-workflow error, not a native
conversion failure or an executable failure.

Recovered the **exact tag-built ZIP**, verified its size/SHA-256 against the
workflow's build summary, and created the release/attached that ZIP through the
GitHub API using the existing checkout credential in memory. No credentials were
printed or saved. No existing release asset was overwritten. The release body
is the tagged `docs/RELEASE-NOTES-v0.11.0.md`.

The follow-up workflow patch uses the actual `forgebridge-dist` paths, accepts a
UTF-8 BOM in JSON, and validates the downloaded layout, package version, ZIP size
and hash **on every build**, including PRs. Publication alone stays tag-gated.
The exact new validation script passed locally against the actual tag artifact.
This patch is separate from the immutable released tag and requires review.
